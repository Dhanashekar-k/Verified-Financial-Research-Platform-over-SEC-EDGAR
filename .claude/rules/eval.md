# Evaluation and reported numbers

- Gold files are read-only for you (see CLAUDE.md rule 2). New candidate rows go to `eval/sets/drafts/`; Shekar promotes them.
- Iterate on the **dev** split. Run **test** only when Shekar asks (milestone end).
- Every reported metric needs n, a 95% bootstrap CI (10,000 resamples) and, for system comparisons, a **paired** bootstrap on the difference.
- `docs/results.md` tables between `<!-- AUTO:START -->` and `<!-- AUTO:END -->` are generated by `eval/report.py` only. Never hand-edit them.
- The baseline and the engine are scored through the same `Answer` schema and the same metric functions.
- The LLM judge must use a different prompt (and preferably a different model) from the verifier's entailment check. Report judge-vs-human κ next to judge-based metrics.
- Prefer `MODE=replay` (cassettes) when only scoring code changed; `MODE=batch` for full runs to halve the cost.
- Never change a tolerance, threshold or gold value to make a number look better. If a target is missed, report it and explain.
